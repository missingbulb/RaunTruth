## 2026-11-15 · born · a method for designing and reviewing task UIs
- **Source:** the owner, after phone ground-truth designs for three studies: "create a skill for
  designing task-implementation-based UIs using the instructions and feedback I gave you here"; the
  feedback was to check each usage hypothesis ("assume you failed - what might have been the
  reason", "what bit of data did you have to have", each UI interaction from the user's eyes and
  fingers) and to keep apart dedicated desktop work from phone work broken into the smallest unit of
  concentration.
- **Actor:** @missingbulb (owner).
- **Model:** Claude Opus 5.5
- **Mechanism:** a workflow skill picked by its description; designing a task UI starts from a
  conversation, not from a file edit a path could predict. It points at
  `designing-ground-truth-tasks` for the desktop page's conventions rather than repeating them.
- **Retire when:** the method moves to a shared canon pack, or no study in this repo builds task UIs
  any more.
